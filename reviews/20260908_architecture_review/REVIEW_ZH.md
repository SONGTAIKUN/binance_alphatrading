# 整体架构与研究路线审查

日期：2026-09-08。审查模型：本轮实际运行的 gpt-6-astra，ultra 推理强度。

本次停止新增策略实验。工作范围是回顾研究历史、核对关键源码、检查已有输出、查阅原始研究文献；没有修改交易策略，没有重新训练，没有重跑完整回测，也没有操作实盘。

## 一、先给判断

**“多币种横截面相对价值 + 风险控制 + 考虑成本 + 时间外验证”值得保留；但目前还不能确认这套具体实现已经形成可靠、可泛化的交易系统。**

最需要调整的不是再换一个因子 family，而是研究闭环本身：

> 先确保衡量的是同一个、可执行的连续组合；再确定信号、标签、风险模型之间的经济含义；最后用受控的搜索预算判断复杂模块是否值得存在。

目前的主要问题按优先级是：

| 优先级 | 问题 | 本次判断 |
|---|---|---|
| 阻断 | 回测不是完整连续持仓账本，跳过时期、fold 边界、成本与风险采样有缺口 | 已从源码与结果确认，应先处理 |
| 高 | 每个验证窗口用很少的组合收益记录，连续选择大量公式和参数 | 已量化；选择噪声与研究者反复使用 test 的风险很高 |
| 高 | alpha residual 与 portfolio risk 的因子坐标不应混同 | 已有版本拆分值得保留；旧 risk 暴露的经济解释还需修正 |
| 高 | 全市场 residual 排名、P4 内部重排、最后真实收益不是同一目标 | 已有多阶段结果表明不能互相替代 |
| 高 | 强约束与 short guard 显著改变信号、实际 gross 和可交易范围 | 已量化；还不能判断有多少是有效风控、多少是误伤 |
| 高 | 当前 AlphaGPT 是候选表达式生成与历史择优，不是已经证明有效的自适应发现器 | 源码已确认；应作为可选模块参加对照 |
| 中高 | 实盘冻结配置和历史滚动重选并不是同一条策略 | 已从 SAFE_V2 入口确认 |

**因此，暂不升级任何“正式交易 baseline”。P15c/P16 可以继续作为研究对照；no-sector 继续作为模型候选，不能因为数值稳定就认定收益更可靠。**

这里也要修正此前过强的说法：“每折参数都只看历史”不等于“整个研究过程从未受到 test 影响”；“约束误差接近零”不等于“实际持仓始终市场中性”；“曲线较平滑”也不等于“已经证明有稳定 alpha”。

## 二、阻断性发现：先确认我们究竟回测了什么

### 2.1 缺失交易时期不是普通报表问题

P15c 核心函数在以下情况下直接 `continue`：有效行不足、short guard 后没有完整多空组合、中性化后仓位为零。它没有在这些分支中记录旧仓收益、平仓成交或现金状态，同时保留此前的 `prev_weights` 和状态。

证据：[P15c 回测主循环](../../scripts/run_p15c_extreme_cluster_turnover.py#L502)。

用已有 fold 日历重新核对，而不是推测：

| 长样本阶段 | 按配置应有决策点 | 实际收益记录 | 未记录决策点 |
|---|---:|---:|---:|
| P4 | 288 | 245 | 43 |
| P3d | 288 | 244 | 44 |
| P9 | 288 | 242 | 46 |
| P15c | 288 | 242 | 46 |

计算依据是各 fold 存储的 `test_start`、`test_decision_end` 与 72h 调仓间隔；当前公共样本是完整小时网格。四个阶段都没有发现记录落在计划网格之外。

以 P15c 为例，32 个 test fold 覆盖 2023-10-15 08:00 UTC 至 2026-06-01 08:00 UTC，共 960 天。242 条记录各表示 72h 持有收益，合计 726 天，占这段日历的 75.625%。其余包含 fold 末端停止新开仓的时间和未记录决策点，不能全部解释为同一种故障，也不能擅自假定都处于现金状态。

真实策略在这些时间只能明确选择：继续持有、减仓、平仓、保持现金，或者某种已定义的故障降级。每一种选择都有对应收益与成本。现在的实现没有把它们统一记入账本。

**这不证明历史收益一定高估，也不证明缺失时期一定亏损；它证明现有结果不能唯一对应一条完整可执行的资金曲线。** 不同候选跳过的时期不同，也会影响模块之间的比较。

### 2.2 Fold 重置了仓位，但没有完整记录边界交易

每次调用回测函数都初始化：

```python
prev_weights = 0
current_state = {}
equity = 1
```

外层按 fold 调用，再拼接 test 收益。可以选择“每 fold 强制清仓”，也可以选择“只更新模型，持仓连续延续”，但二者必须明确：前者要记录末端平仓与下一期开仓成本，后者要传递仓位、现金、持有年龄、挂单与实际权重。

目前的实现相当于在 fold 内保留目标仓位，在 fold 之间重置，却没有相应的完整交易记账。单纯 purge 掉末端标签不能替代平仓核算。

### 2.3 换手是目标权重之差，不是实际交易名义金额

当前主要计算：

```text
turnover = sum(abs(new_target_weight - previous_target_weight))
cost = turnover * fixed_one_way_bps
```

上一期价格变化和净值变化以后，实际权重已经不等于上一期目标权重。对于线性 USDT 永续，交易数量、当前价格、合约规格和账户净值决定真实调仓名义金额。目标不变也可能需要交易；目标改变也不意味着交易量恰好等于上述差值。

这对 turnover penalty、no-trade zone、partial rebalance、cluster turnover guard 的评价都有直接影响。不能把这类账本问题当作最后才补的“工程细节”。

### 2.4 72h 终点回撤不等于持仓期间最大回撤

当前主要收益行使用 `weights * fwd_simple_ret_h72`。这在特定静态持仓、执行价格与资金假设下可以成为简化端点近似，但不是小时盯市曲线。

因此：

- 72h 内先大亏再反弹，终点收益可能很好；保证金压力、止损和实际最大回撤却可能很差。
- beta、gross、单币权重在价格变化后会漂移；入场时合规不能证明持有期间合规。
- Sharpe 按已记录行的均值和标准差乘 `sqrt(365*24/72)`；缺失时期未进入日历序列，不能直接视为连续日历 Sharpe。
- 最大回撤函数没有把初始净值 1 放入历史高水位。该项在本次四个阶段的全样本 8bps 结果中没有改变数值，但在以亏损开头的子区间或 fold 中可能影响统计。

证据：[绩效统计](../../src/crypto_stat_arb/portfolio.py#L536)。

输出行的 `timestamp` 还是决策时点，而该行收益要到 `exit_timestamp` 才实现。如果未来以策略已实现净值作为 gate，必须按收益实际实现时间读取，不能在决策时就使用这一行完整收益。本次没有据此断言当前所有 gate 都存在这种泄漏。

### 2.5 Funding 特征不等于 funding 收支

这条历史回测主路径的净收益是价格贡献减固定交易成本，没有按实际 funding 结算时点和持仓方向记录资金费收支。

这不仅影响最终 net，也影响研究问题：用 funding 排名后只检验价格反转，并不能充分评价“收取 carry”的策略。funding 既可能是特征，也可能是现金流，二者不能混为一谈。

**建议首先建立：价格损益、资金费收支、手续费、滑点、其他费用分别列示的连续账本。8bps 只代表交易摩擦假设，不自动包含整个持有期的 funding。**

## 三、第二个根本问题：搜索能力超过了样本的辨别能力

### 3.1 本次量化的搜索规模

| 每个 fold 的阶段 | 候选评估数量 | 每个候选实际验证收益记录中位数 |
|---|---:|---:|
| P4 committee/参数 | 252 | 52 |
| P3d 公式及混合参数 | 540 | 25 |
| P9 衍生品增量 | 459 | 25 |
| P15c cluster 参数 | 36 | 24.5 |

这些是已有验证 CSV 的实际统计，不是用小时数推算。它们是组合收益记录数，并不是独立样本数；独立信息量通常更低，也不能把各阶段候选数简单相加后视作独立检验次数。

当前 P4 在整个 180 天历史训练段比较参数；后续 P3d/P9/P15c 在其中最近约 90 天继续择优。上游参数已经利用了这段数据，后续又复用它来评价新模块。外层 test 仍可以没有直接进入当折选择，但内层表现会受上游筛选影响，不能把这一串选择当作互相独立的验证。

证据：[P4 选择窗口](../../scripts/run_p4_nested_walkforward_selection.py#L89)、[本次搜索规模审计](existing_output_audit.json)。

### 3.2 三种“防未来”必须分开

1. **特征时间因果性**：时点 t 的特征只用当时已发布数据；滚动 beta 不能使用未来收益。这方面已有数据和 residual 审计值得保留。
2. **单次实验的选择因果性**：当前 test fold 的标签不参与该 fold 的公式、参数选择。长历史 nested pipeline 和后续部分实验确实在落实这一点。
3. **研究过程的选择偏差**：研究者反复查看同一段 test，随后选择 family、修改 guard、改变接受标准、选择最漂亮版本。下一次重跑 nested 不会消除这些已获得的信息。

P9 早期清理包就明确记载：它不是重新搜索，而是在既有 P7b 选择上，删除 P8 发现脆弱的 K01 并限制增量权重。这个包不能因为保留原来的 fold 文件，就把后加规则也称为当时已确定的 OOS 规则。后来的长历史完整重选是更好的证据，但仍不是一个从未参与研究的外部世界。

证据：[早期 P9 包的声明](../../docs/history/early_p9_clean_baseline_REPORT.md)。

反复试验造成选择偏差是已有研究明确讨论的问题，并不是加上 walk-forward 名称就能消除。[Bailey 等：The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。

### 3.3 不应该再把所有失败都解释成“下个 selector 会更聪明”

P27 原生搜索的 test slow Rank IC 仍然为正，但 q25 为负、公式与执行参数频繁变化。P28 固定 family/收缩并没有解决交易收益问题；P29 改成 P4 pool 内尾部目标后，nested 仍全部 fallback。

这支持“信号弱、同质化、选择不稳定”的判断，但还不能精确分解各原因。当前记账问题也可能影响某些候选的相对排名。应当降低选择自由度、修正共同评价口径，而不是在原有闭环里继续增加硬拒绝条件。

建议把现有历史定义为**研究开发样本**。冻结下一版协议和试验预算后，才开始积累真正未参与决策的新时段。较晚的日期不自动等于未观察样本，必须核对是否已被之前研究或实盘观察使用。

## 四、AlphaGPT 模块到底在做什么，是否必须保留

### 4.1 本地实现，不应与名字混淆

当前核对的慢因子链路是：

```text
人工 primitives、种子公式、允许的操作符
    -> 固定随机种子生成一批表达式
    -> 去除重复文本、过滤语法
    -> 每个历史窗口计算候选得分和回测指标
    -> 选择验证期表现最好的公式及混合权重
    -> 下一段 test 应用
```

`generate_formula_specs()` 使用 `random.Random(seed)`；随机递归构造 ADD/SUB/MUL/DIV_SAFE 等表达式。P3d 在生成各 fold 的任务之前建立候选全集。这条路径没有看到根据 fitness 更新生成器、强化学习训练或代际进化反馈。

证据：[公式生成器](../../scripts/run_p5_alphagpt_slow_search.py#L484)、[候选池构建位置](../../scripts/run_p3d_p4_gated_rerank_alphagpt.py#L115)。

所以，“每折重新选择因子”大体成立；“每折由一个已训练的 AlphaGPT 重新发现新的经济规律”不符合这段实现。原始项目或其他论文中的 AlphaGPT 能力，不能直接归到当前脚本上。

### 4.2 公式数不等于信息源数

P28 的相关矩阵谱诊断给出：240 个名义公式，participation ratio 约 3.1。它是特定样本下的有效维度指标，不是严格证明“世界上只有三个 alpha”。但它确实提示：大量表达式是在重复读取相近信息。

更直接的例子：C09 不是独立于 A07 的第三条原始信号。它包含：

```text
C09 = 0.35 * A07
    + 0.35 * B12
    + 0.30 * liquidity_quality
    - 0.20 * vol_of_vol
```

后续又把 A07 与 rank(C09) 混合，并允许 NEG(B12) 增量。NEG(B12) 有可能是在抵消既有组件，而不是贡献一个独立信息源。因为中间有 rank 和其他变换，不能直接把最终权重代数展开成上述线性式，但信息重叠的事实仍然成立。

证据：[C09 定义](../../scripts/run_p2_manual_slow_alpha_grid.py#L261)。

### 4.3 模块定位建议

把 AlphaGPT 降为**可选表达式候选生成器**，不是整个系统必须围绕的核心。

它应该在同一连续账本、同一成本和风险预算、同一时间外协议下，证明自己优于少量经济因子、简单收缩加权或正则化线性组合。没有增量时可以关闭；这不是否定统计套利，也不是证明所有机器学习方法无用。

P28 已经尝试过 family ensemble，不能再原样重复并承诺有效。下一次简单模型对照的目的应是定位复杂度是否必要，而不是预设“简单模型一定赚钱”。

## 五、Residual 与 Risk：最重要的是经济含义，不是数值更漂亮

### 5.1 Residual 不是自动存在的均值回复机会

回归得到的 residual 是相对于所选因子模型的未解释收益。OLS 的样本正交性不等于未来均值回复，也不等于能覆盖成本。

把每小时、每次使用不同历史 beta 得到的 residual 累加成 residual price，再计算 z-score 或 OU half-life，是一种信号构造。它不自动等价于一个固定对冲组合的自融资价差。必须分别检验未来相对收益的预测性、衰减、路径和交易可实现性。

因此，从单 pair 切换为 residual 横截面排序是合理的研究方向，但不能把“去掉市场影响之后剩下的部分”直接定义为“真实错价”。残差中仍然会有未建模风险、趋势、跳跃与噪声。

经典 residual stat-arb 研究本身也展示了危机时期的明显回撤；该范式不是跨任何 regime 都盈利的保证。[Avellaneda 与 Lee：Statistical Arbitrage in the U.S. Equities Market](https://math.nyu.edu/~avellane/AvellanedaLeeStatArb071108.pdf)。

### 5.2 Alpha 模型和 Risk 模型要分开，这是应正式保留的修改

**Alpha residual model** 回答：怎样转换历史收益，更容易提取未来相对表现信息？

**Portfolio risk model** 回答：当前实际组合暴露于哪些共同风险，要容忍、限制或对冲多少？

两者可以使用不同因子和估计方法，但字段必须带清晰版本，不得把同名 beta 不加说明地互换。P26 引入的命名空间、标签恒等式和审计应该保留。

no-sector 减少共线性、修复 majors sector 结构缺陷有真实价值；但其目标是降低模型估计不稳定，不是保证更高 alpha。FF-like 加入 momentum/carry 因子，也可能剥离本来希望赚取的风险溢价。是否中性化某个 style，应是经济目标的选择，不是“因子越全越好”。

### 5.3 旧版风险暴露并不处于完全相同的因子坐标

旧 `add_factor_inputs()` 对每个币构造 ex-self market/sector；BTC 自身的 BTC 因子设为 0，ETH 自身的 ETH 因子设为 0。

用 ex-self 避免 alpha 回归中的自我解释有其理由，但这意味着各币回归里的某些因子收益不完全相同。把这些 beta 直接放在一起要求 `sum(w_i * beta_i)=0`，只能证明代码中的系数加权和为零，不能自动证明组合对同一可交易 market/BTC/ETH 因子真正中性。

证据：[旧因子输入构造](../../src/crypto_stat_arb/factors.py#L33)。

后续 risk 模型应显式采用共同的风险因子定义，或先把各币系数转换到可比较坐标。若 BTC 本身就是可交易 BTC 对冲工具，它对该工具收益的直接敞口不能仅由“自身回归中删掉的 BTC 列”来解释。

**这是比继续比较 ridge 与 OLS 谁的 beta 更平滑更优先的架构检查。** 该问题不必然造成逐行未来泄漏，却可能使“严格中性”的经济含义失真。

## 六、目标错位：IC、尾部排名、组合收益必须拆开

当前链路至少有三种不同任务：

1. 全部 20 币的未来标准化 residual 排名。
2. P4 已允许的 long/short pool 内，候选是否选得更好。
3. 加入中性化、风险限制、调仓、交易成本和资金费后的账户收益。

第一种好，不保证第二种好；第二种好，也不保证第三种好。候选在中间排名区间的改进，可能完全不改变仓位。原本在 P4 pool 外有效的信号，也可能在 gated rerank 中无处发挥。

因此要区分：

- **独立 alpha 测试**：这个经济变量本身是否有可交易信息？采用事先固定的简单组合验证。
- **P15c 增量测试**：在旧 pool、旧风险预算下，它是否带来额外价值？这是更窄的问题。

P29 的失败可以说明当前 S1 没通过那一套 pool 内增量协议，不能扩展成“该类信号在所有组合方法下都不存在价值”。反过来，也不能因为其全市场 IC 为正就继续强行接入 P15c。

标签方面，建议保留多个 terminal horizon、t 时刻 beta 固定的未来 residual、ex-ante 波动归一化、centered rank 和独立 adverse-excursion 字段。`label_slow_low_turnover` 的名字不应被当作低换手保证，它只是多期限目标的组合。

72h 调仓、72h 终点标签、168h composite、最低持有期、EMA 衰减不是同一个时间尺度。应该根据训练段的信号衰减与交易政策明确它们的关系，而不是靠更多搜索参数自动解决。

另一个值得保留为后续专项检查的点：当前 signed path-aware label 根据未来 terminal 的正负选取 adverse penalty，这作为目标本身不是未来特征泄漏，但可能改变原本的收益方向排序。若直接用来决定多空，它未必等价于任一侧实际效用。更清楚的做法是把 long 与 short 的路径风险分别输出，与 terminal 方向目标分开使用。

证据：[慢标签实现](../../src/crypto_stat_arb/slow_labels.py#L43)。

## 七、组合层：风险约束可能已经成为主导模块

当前 constrained allocator 主要最小化：

```text
sum(penalty_i * (weight_i - raw_target_i)^2)
```

同时要求净敞口和指定 beta 等式约束、单币上限、gross 不超过上限。非原始选中币可以作为 hedge，偏离惩罚默认更高。它是受约束的目标投影，并不是直接求“预期净收益最大的权重”。

证据：[权重优化器](../../src/crypto_stat_arb/portfolio.py#L404)。

本次长历史 P15c 的**已记录时点平均实际 gross 只有 0.2615 倍净值**，并非 1 倍。short guard 每期平均移除约 2.19 个 short 候选。这个平均值还不是包含全部现金和缺失时段的日历平均。

如果只允许原始 4 long + 4 short，且每币上限 12.5%，达到 1 倍 gross 就要求八个币全部顶格，几乎没有再调整 beta 的自由度。实际代码允许额外 hedge 和降低 gross，所以可以求出解，但信号的承载方式已与“买最高四个、卖最低四个”明显不同。

这可能是有效保护，也可能是风险模型噪声把 alpha 压掉，不能只看最终回撤判断。特别是加更多 exact neutral、cluster cap、side guard 后，策略变稳有时只是承担的风险和仓位变少。

后续必须报告完整转换过程：

```text
原始 score
-> eligible pool
-> 未约束目标
-> 中性化目标
-> guard/cluster 后目标
-> 成交后真实持仓
```

每一步记录 gross、共同因子暴露、预测收益保留率、方向翻转、被取消的 alpha 仓、额外 hedge 名义金额和成本。比较候选时同时做可执行的相同风险预算对照，不能事后用全样本波动率随意放大较低风险的曲线。

建议保留单币上限和必要风险限制；不要追求 noisy beta 达到 `1e-14` 就认为胜过容忍小幅估计暴露。共同风险模型确认以后，可比较合理暴露容忍带或风险惩罚。不是建议取消中性化，更不是现在把 gross 直接放大到 1。

## 九、统计名称也要审计，不能把诊断值当认证

P28 有两处尤其需要降级解释：

1. “PBO 62%”来自 P27 最终选中过的 20 个公式，在 32 个 fold 的 IC 矩阵上随机分半择优。它是特定候选子集、特定 IC 指标的事后诊断，不是整个交易系统有 62% 概率过拟合，更不是完整搜索历史的正式概率评估。
2. `deflated_ic_table()` 用标准正态最大值近似直接作为 ICIR 门槛，未估计相应 trial 统计量分布的尺度；其输出不能直接作为标准 Deflated Sharpe Ratio 的显著性结论。原始 DSR 方法需要考虑试验统计量的方差等信息。

证据：[P28 诊断候选矩阵](../../scripts/run_p28_stable_family_ensemble.py#L500)、[deflated IC 实现](../../scripts/run_p28_stable_family_ensemble.py#L554)、[Bailey 与 López de Prado：The Deflated Sharpe Ratio](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)。

另外，当前 `short_abs_contribution_share` 使用的是两侧累计净贡献的绝对值之比，不是 short gross、short 风险或逐笔绝对损益占比。long 内部盈亏互相抵消后，该比例可能变化很大。以此设 70% 硬门槛，不能等价于“short 风险占比不超过 70%”。

证据：[贡献比例与 fitness](../../scripts/run_p3d_p4_gated_rerank_alphagpt.py#L492)。

此类指标应保留原始构成并按真实含义命名。组合期望损失、单边 stress 损失、gross 占比和净收益来源是四种不同问题。

## 十、按十个模块重新定义职责与交接

### 1. 数据层

输入为原始 OHLCV、funding、premium、OI、ratio 与合约规则。输出应是按时点可获得的数据快照：不仅有 `event_time`，还要有 `available_time`、来源、缺失/陈旧标记、有效 universe 和版本。

价格转 log return、OI/volume 使用适合的 log/change、有符号 funding/basis 保留方向、滚动标准化与稳健截断，这些有必要，但必须遵循各字段定义。不要对所有字段统一做 log，也不要通过回填掩盖陈旧数据。

现有固定 20 币公共历史适合回答“这 20 币在共同存在期间”的问题，不等于 point-in-time 全市场 universe。它始于新币上线后的 2023 年，也没有覆盖 2022 年。扩大外推结论前需要历史可交易性与 survivorship 口径，不是简单把起始日期往前写。

20 个相关性很高的主流币也不能直接类比数百只股票的统计套利横截面。可用于分散误差的独立机会较少，BTC/ETH 还同时承担风险代理和交易资产角色。未来扩大 universe 可能改善广度，但会引入流动性、上市历史、退市和成本问题；当前不应直接用全市场下载来替代这个问题的论证。

### 2. Residual / Risk Model 层

从历史快照产生两组版本化输出：alpha residual/beta 和共同风险暴露/协方差。滚动估计使用当时允许的信息；风险模型输出必须对全部资产具有一致解释。

交给因子库的是 residual 历史及过去质量指标；交给 allocator 的是共同风险矩阵及不确定性，二者不能隐式共用字段。

### 3. Label 层

它是离线学习支路，输入已结束的未来路径，输出终点 residual、不同 horizon 的标准化/rank 标签、多空各自 adverse excursion 与 label end time。

训练选择只能读取已经闭合的 label；执行层不得依赖未来 label 是否存在来确定当时可交易币。当前静态完整样本下，主路径的有限 label 筛选未必改变大部分历史币池，但动态 universe 和缺失数据情形必须独立防护。

### 4. 因子库

输出已知时点的特征向量，不直接输出“保证有效的 alpha”。每个 feature 应注明经济假设、原始来源、窗口、可见延迟、residual 版本、预期速度和失败情形。

区分三类角色：收益预测器、风险/状态变量、交易可行性变量。同一个变量可以承担多个角色，但要分别验证。所谓“风险变量库”首先是待验证库存，不应因为被存进去就自动获得拦截交易权限。

### 5. AlphaGPT / 因子组合器

输入因子库和冻结搜索规则，输出候选公式/组合及完整 provenance。它不应读 test 标签，也不应把公式数量当作独立信息数量。

先有少量简单经济模型的对照，再决定是否需要符号搜索、条件权重或复杂非线性。候选池、种子、筛选过程都应随模型 artifact 保存。

### 6. Score / Selection Protocol 层

输入训练/验证结果，输出在未来区间冻结的 score 模型、权重、接受/fallback 决策及适用范围。rank 是序数，不等于预期收益 bps，不能未经标定就当作 cost-aware optimizer 的绝对收益参数。

避免同时在很小 validation 上最大化十余个噪声指标。明确一个主要经济目标，风险约束另列；成本情景与复杂度预算预先声明。要求 tail 不脆弱合理，要求所有指标和所有市场都改善则容易使选择失效或筛到偶然满足全部条件的候选。

### 7. Long / Short Pool 生成层

先依据交易条件确定 tradable universe，再依据 score 确定 eligible sides；持有状态与 entry/exit hysteresis 必须对应真实时间。

P4 gated pool 可保留用于增量实验，但不能让它成为检验所有新 alpha 的唯一入口。pool 缺少一侧时必须输出明确动作，不能跳过账本。

### 8. Allocator / 中性化 / 风控层

输入 score 或经过标定的预期收益、共同风险矩阵、真实当前仓位、限制与成本，输出目标数量/权重和约束诊断。

需要知道“哪项约束改掉了哪些 alpha 仓位”。临时不可行时选择保持/降仓/清仓策略并记账，不允许通过零仓返回值让整个持有期从评估中消失。

### 9. Execution / Turnover / Cost 层

输入目标与真实持仓，输出订单、成交、数量变化、现金流、价格损益和 funding。信号可以 72h 更新，但风险与账本至少按数据允许的更细粒度更新，两个时钟必须分离。

EMA/tau、no-trade、partial rebalance 都是交易政策，不是新增预测信息。既有交易成本研究强调信号衰减、未来目标与成本共同决定调仓速度，不支持“越慢越好”。[Gârleanu 与 Pedersen：Dynamic Trading With Predictable Returns and Transactions Costs](https://www.aqr.com/insights/research/journal-article/dynamic-trading-with-predictable-returns-and-transactions-costs)。

### 10. Walk-forward / Evaluation 层

调度训练截止、标签闭合、模型生效和连续组合推进；不是简单把各折从零开仓的结果拼起来就结束。

应输出完整日历净值、实际费用、资金费、风险预算、分侧分币贡献、候选选择记录、因果性测试结果和统计不确定性。fold 之间模型可以变化，账户状态仍须遵循一套明确规则。

## 十一、研究与实盘还有一处策略身份差异

SAFE_V2 的 `apply_latest_locked_score()` 读取 P9/P16 选择表后，按 fold 排序取最后一行；衍生品增量不是 fallback 时还会直接报不支持。

证据：[SAFE_V2 锁定配置入口](../../docs/history/safe_v2_strategy_reference.py#L251)。

冻结最后一个模型运行并非天然错误，可以是合法部署方式。但是，它和历史上每 30 天重新选公式/参数的策略不相同。需要明确要验证的是：

- 冻结模型未来持续运行；还是
- 按固定训练截止、训练方法、更新频率滚动产生新模型。

两者的模拟与实盘必须一致。执行安全、文件校验、重启恢复等建设值得保留，但不能为另外一条学习策略的收益背书。

## 十二、建议的大方向调整与推进门槛

### 第一步：先固定“可执行策略”的定义

不新增 family、不追加 AlphaGPT 搜索、不因某个已知坏 fold 再加专用 guard。冻结现有研究结果、配置与源数据版本。

明确初始资金单位、永续数量/名义金额、模型更新时间、信号时钟、风险时钟、没有候选时的动作、fold 边界持仓、资金费和成本定义。

验收不是收益变好，而是同一组目标指令在研究回放与模拟执行中产生一致的仓位与账本。

### 第二步：修复共同评价引擎，再复核旧结论

先用人工可验算的小例子验证：跨 fold 不换仓、完全平仓、无候选、价格大幅变化后的调仓、funding 正负、成本抵扣、部分成交、现金时期以及持有期内先跌后涨。

对线性合约，应能逐项核对类似以下资金变动，实际符号和时点依交易规则定义：

```text
账户权益变化
= 上期真实持仓数量对应的价格损益
+ 资金费及其他持有现金流
- 成交费用
- 相对估值价格的执行损耗
```

每个日历时点都有唯一账户状态，所有订单与成本可追溯；不存在无收益记录却保留不明旧仓的时间。随后才重放少量旧策略作 matched comparison。

### 第三步：在同一账本上做最小模块消融

不是再跑一千个参数，而是预先限定少数对照：简单经济信号、P4、P4 加当前符号候选、P9、P15c。分别报告同资金与同事前风险预算口径。

输出“信号 -> pool -> 约束 -> 执行”的收益和风险变化。先确定是基础 alpha 弱，还是 selector、pool、risk projection 或执行造成主要损耗，再决定改哪一层。

no-sector 与旧 alpha residualizer 可以在这个受控设计中成为模型对照，但共同 portfolio risk 的语义必须先统一。不要同时更换标签、公式语言、risk 模型和调仓规则，再把整体差异归因给其中一项。

### 第四步：约束研究自由度，验证增量

为整个学习策略规定搜索预算与主要目标；后续模块如使用上游模型的历史预测，优先使用当时可生成的时间外预测，而不是用已在同段择优过的最佳模型追溯评分。

推断以时间块为基本单位，考虑标签重叠与资产相关；保持完整试验清单。bootstrap、PBO、DSR 等只有实现与输入符合假设时才使用，不能靠复杂统计名称替代未观察样本。

硬门槛应围绕真实风险和交易可行性；不必要求每个 regime 盈利，也不必要求收益曲线肉眼单调向上。更合理的是：经济来源可解释、成本后存在有不确定性说明的增量、风险受控、非少数幸运样本主导、没有大幅增加策略选择自由度。

### 第五步：通过以上门槛后，再扩展新信息

先前的 OHLCV/residual/derivatives 并非已经穷尽其全部可能，但当前结果也没有理由支持继续只靠重组同一批字段期待质变。

跨交易所 funding/basis dispersion 等具有不同经济来源，可以作为之后的信息扩展候选；是否可交易还取决于时间同步、合约可比性、实际持有现金流和单交易所/多交易所执行约束。新闻不是当前最先要补的洞，更复杂数据也不能修复错误评价器。

用户已测试的不超过 8bps 可以作为主成本情景的起点；应保留按币种、行情和订单方式变化的成本与资金费，20/30bps 用作压力测试。没有必要为了通过不适用的全程 30bps 硬标准，把所有 8bps 有效信号都筛掉。

## 十三、什么情况下可以继续，什么情况下应该换路线

**可以继续精细因子研究的前提**：连续账本与因果性测试通过；alpha/risk 语义明确；候选比较具有一致可执行口径；至少一个简单、可解释信号在冻结协议下显示值得进一步验证的净增量，而不是只剩同一 baseline 的机械 fallback。

**若修正后，简单模型和复杂搜索都没有净增量**：停止同源公式扩张，把研究资源转向不同经济来源，或者承认当前 universe、持有周期和单交易所执行条件下没有足够证据支持这条策略。

**若简单模型有增量、AlphaGPT 没有**：删除或限制组合器，保留交易系统。工具的存在不是研究目标。

**若信号有增量、约束后消失**：检查共同风险定义、池限制、风险预算和对冲实现，不应立即放宽风险去追收益。

**若只有低成本、特定 regime 有效**：这可以是一条有明确容量和适用范围的策略，但不能宣传成全市场、全时期都稳定的通用套利机器。

本次不能保证未来盈利，也不能证明修好账本后 P15c 的收益一定上升或下降。能够明确的是：**继续细调因子前，应该先让系统有能力可信地否定自己的结果。否则越多实验越难知道哪一步真的产生了价值。**
